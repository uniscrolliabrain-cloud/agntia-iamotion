# Layout y migración propuesta
library/assets/ conserva binarios por hash; library/inventory/ y library/cards/ fuentes inmutables; library/entities/ legado V1; library/generated/<snapshotId>/{binary,visual,claims,relations,rag,index}/ derivados; library/reviews/append-only/ decisiones; library/catalog/current.json puntero; library/taxonomy/ vocabulario versionado; lab/staging/<runId>/ temporal no público; lab/observability/runs/<runId>/ recibos redactados.
Manifest {schemaVersion,snapshotId,parentSnapshotId,inputHashes,toolVersions,files:[{path,sha256,bytes}],counts}; snapshotId hash del manifiesto sin snapshotId ni timestamps. Canonical JSON: claves ordenadas, arrays semánticamente ordenados solo cuando conjunto, UTF8, finitos, sin undefined. Orden de keyframes se conserva. Validar paths POSIX relativos sin .., symlinks ni colisiones casefold. No incluir binarios en SDK.
Migración: freeze V1 -> inventory dry-run -> assign IDs ledger -> build staged snapshot -> compare coverage -> review -> commit pointer CAS. Rollback pointer al snapshot anterior; no revertir ledger ni borrar evidencia. Si se retira activo por derechos, denylist efectiva también para snapshots antiguos. Retención y limpieza requieren política explícita.
